## 基础概念
LLM本质是无状态的，为了实现记忆需要将之前的对话历史连同当前的问题一起发送
每个模型都有一个记忆上限，称为“上下文窗口”，通常以 Token为单位

记忆类型：
- 短期记忆：模板正在处理和关注的信息，受限于模型的上下文窗口；包含当前系统提示词、当前轮次的历史对话、Agent执行多步推理的中间状态等内容
- 长期记忆：持久化存储并在需要时被召回的信息，通常依赖于外部存储（向量数据库等）

## 上下文压缩
解决的核心问题：在有限的注意力预算内，让模型看到最关键的信息

### 核心认知
- 上下文压缩的本质是注意力管理
不是在尽量多地保留信息，而是在确保模型当前决策所需要的信息在它的注意力范围内

- 压缩和恢复必须是一体的
压缩不等于删除，只是暂时移出视野

- KV Cache 是被严重低估的优化维度

- 没有银弹，但有清晰的优先级
  - 先管住入口：不必要的信息不要放进来（Cursor 的按需加载、Manus 的小工具集）
  - 再管住工具结果：这是最大的 token 消耗源（截断、compact、清除）
  - 然后做对话压缩：Compaction / Summarization
  - 需要的话拆 Agent：上下文隔离
  - 兜底靠文件系统：外部记忆，比如 openclaw 的多级 memory 机制。

### Manus：缩减&卸载&隔离
- 缩减
  - Compaction 紧凑化
为工具结果维护“完整版”与“紧凑版”。老结果只留指针（如文件路径），新结果保持完整。核心原则：所有压缩必须可恢复。

  - Summarization 结构化摘要
当老结果都处理完，但窗口还是太大的时候会进行摘要，并且用***预定义的schema***来约束摘要格式，保障了摘要质量的稳定，避免模型在总结时抓错重点

- 卸载
  - 外部记忆：将大量信息写入sandbox文件系统，模型按需读取，不会全部塞进prompt
  - 原子化工具：只保留20个基础工具，复杂功能通过CLI暴露
  - KV Cache优化：利用Response Prefill（`assistant: <tool_call>{"name": "browser_` => 模型只会调用browser的能力）来动态控制工具调用，而不是增删工具定义

- 隔离
多Agent架构：子 Agent 的主要目标不是按角色分工（设计师、工程师等），而是隔离上下文，防止长对话互相干扰

### Claude code：三层防线
1. Tool Result Clearing："成本最低、风险最低"的压缩操作——对话深处的工具调用结果，模型不再需要了，直接清掉。几乎没有信息损失，因为那些老结果早就被消化过了

2. Compaction：对话快到上限了，让模型读一遍完整历史，生成结构化摘要。这个摘要会保留任务进度、当前在做什么、已做的决策和原因、未解决的问题。压缩完带着摘要 + 最近 5 个文件继续干活

3. 子 Agent：复杂任务拆给子 Agent，各自在干净上下文里工作

### Cursor：Dynamic Context Discovery
工具描述按需加载，大输出写文件，Agent用grep/tail按需读取

### LangChain：自主压缩
不是固定阈值触发，而是Agent自己判断是个好时机然后触发压缩。比如：
- 准备开始消费大量新信息
- 刚完成一个子任务，中间状态已经转化为结果
- 从大量数据里提取完结论后，原始数据不再需要
 
### 基本的优化策略
- 滑动窗口：只保留最近N轮对话
- 增量摘要：将之前的对话压缩成精炼的“事实摘要”，放到System Prompt中
- 压缩：
  - 基于困惑度（Perplexity）或信息熵，去掉废话，保留信息量最大的Token
  - 可逆的信息缩减，将信息的一部分外化到文件系统里，同时在上下文中保留可以重建完整信息的线索（如：path+content）
- 任务拆解：分解给多个sub-agent，每个都拥有独立、更小的上下文窗口
- RAG：将历史对话存入向量数据库，根据问题语义检索最相似的Top-K历史片段
