## 概述
一个上下文里包含：
- System Prompt：身份、规则、工具定义
- 对话历史：用户消息+模型回复
- 工具调用记录：调用参数+返回结果

各种压缩手段核心是为了处理：**工具结果和对话历史里，哪些还有用，哪些可以扔掉或者缩短**

## Claude Code 三层压缩
### Layer1 Microcompact
不删消息，不改对话结构，只是把**老旧的工具结果缩小**
- 在30轮时，把第3轮的工具结果替换成`[Old tool result content cleared]`，模型后续的决策大概率不需要依赖它了；修改后消息结构完好无损，但token占用下降
- 主要有两类的工具结果可以被清理：一类是清理工具返回结果的：Read、Grep等，查询类工具的结果是一次性的；一类是工具调用参数的：Edit、Write，因为他们的输入参数（如：文件完整内容）往往比返回值更大
- 会保留最近N轮的工具结果不动，因为很可能还在被模型引用

### Layer2 Snip
从对话历史的头部开始删，直接砍掉最老的消息，保留最近的上下文
- 定位是快速释放空间，不会调用LLM生成摘要
- 需要保证消息序列的合法：第一条消息是user角色、tool_use和tool_result必须成对出现
- 砍完后会插入一个边界标记，模型看到这个标记知道可能遗漏了一些早期信息，会更谨慎地做判断

### Layer3 Auto-compact
调用LLM对整个对话做一次摘要压缩

#### 触发阈值
effectiveContextWindow 是上下文窗口大小减去摘要输出预留的 20K token。对于 200K 窗口的模型，大概是在 167K token 时触发
摘要本身需要空间来生成，而且不能等到彻底满了才开始，需要得给 summary 本身留点空间
```
触发阈值 = effectiveContextWindow - 13K(缓冲)
```

#### 压缩步骤
1. 剥离图片：图片token较大，对摘要来说也没有意义，所以把所有图片替换成`[image]`的文本标记
2. Fork一个子线程生成摘要，不阻塞主循环继续响应用户
3. 生成摘要：LLM收到的指令会先写一段`<analysis>`分析，再写`<summary>`摘要。摘要本身是一个严格的结构：用户意图、技术概念、文件改动、错误修复、问题解决、用户消息、代办任务、当前工作、下一步
4. 恢复关键任务：压缩完后模型的上下文里只有摘要和最近几轮对话，会重新附加最近读过的5个文件内容，确保模型不会因为模型就失忆正在操作的文件
5. 替换消息：把旧的消息列表替换成下面的结构
```
[压缩边界标记]
[摘要]
[恢复的文件]
[最近的对话]
```

## OpenClaw 四层压缩
### Layer1 Tool Result Context Guard 工具结果实时截断
不是等老旧的工具结果过期了再清理，而是在每次准备发送上下文给模型之前，就对所有工具结果做实时检查和截断
截断限制不是固定的，基于当前模型的上下文窗口动态计算：
- 单个工具结果上限：上下文窗口的50%
- 总上下文预算：上下文窗口的75%

超限的时候，先对单条做截断，在内容70%的位置找最近的换行符切断，附加`[truncated: output exceeded context limit]`
如果截完单条还是超预算，会对最老的tool result开始，逐条替换成`[compacted: tool output removed to free context]`，直到总上下文回到预算内

### Layer2 History Turn Limiting 历史轮次裁剪
- 砍掉最老的对话，给上下文腾空间，但是按轮次计数而不是按token数
- 会保留N轮user turn及其关联的assistant回复和tool result，最早的直接丢弃
- 裁剪后会做一轮tool_use和tool_result的配对修复

### Layer3 Compaction Safeguard LLM 结构化摘要
触发时机和Claude Code类似，pi-coding-agent框架在检测到上下文接近窗口上限时自动触发

#### 第一步 分离可压缩和要保留的消息
默认保留最近3轮对话不动，保留的消息包括完整的user/assistant交互及其关联的tool result，剩下的会进入压缩流程

#### 第二步 Token估算与分段
chars / 4 的启发式方法估算 token 数，加 1.2x 安全系数，然后把消息切成多段，每段不超过模型能处理的范围

#### 第三步 分段摘要&合并
每段独立调用LLM摘要，多段再合并成最终版本，解决了压缩的对话可能比模型输入还大的问题

#### 第四步 结构化输出
摘要不是自由文本，必须包含5个固定section：
- Decisions：做了哪些决策
- Open TODOs：还有哪些代办
- Constraints/Rules：有什么约束和规则
- Pending user asks：用户还有什么未回应的请求
- Exact identifiers：关键标识符的精确值

#### 第五步 质量守卫
摘要生成后，检查5个section是否齐全、关键标识符是否被完整保留、最近一次用户请求是否在摘要中有体现。如果不通过就会重试

### Layer4 Overflow Compaction 溢出重试
前面几层都没把上下文压缩到窗口之内，会进入最后的兜底机制：
- 检测到溢出错误后，最多重试 3 次
- 每次重试都会再跑一轮 Compaction
- 如果 3 次压缩都不够，最后手段——激进的工具结果截断，把所有大的 tool result 一次性砍到极限

## Manus 可恢复压缩 + 文件系统卸载
> 理念：所有压缩都是可恢复的

Manus 给每个工具调用维护两个版本：完整版和紧凑版。完整版是原始工具输出，存在 sandbox 文件系统里；紧凑版只保留一个引用，比如文件路径。随着对话推进，老的工具结果从完整版切换到紧凑版
信息没有真正丢掉，只是暂时不在模型的"视野"里。需要的时候，模型可以通过文件路径把完整内容读回来。上下文是可逆、可恢复的

## 压缩策略小节
1. 先管住入口：不必要的信息不放进来
2. 再管住工具结果
3. 然后做对话压缩
4. 需要的话拆agent：上下文隔离
