## 设计哲学

### 异步流式优先
传统的LLM调用使用请求-响应模式：发送Prompt，等待完整响应，处理结果
但Agent会在一个用户请求中执行多轮工具调用，都可能产生需要实时展示给用户的中间状态：工具调用计划、执行进度等

所以使用AsyncGenerator，只需要一个for await ... of就可以消费整个对话过程的所有事件
```js
async function* runClaudeStep() {
  yield { type: 'thinking', content: '正在扫描目录...' };
  const files = await callTool('ls'); 
  yield { type: 'tool_result', data: files };
  yield { type: 'code_chunk', content: 'export const ...' };
}
```
- 增量输出：通过yield逐步产出流式事件，可以实时渲染
- 可中断：随时通过 `generator.return` 活 `generator.throw` 终止生成器
- 背压控制：由消费者 `.next()` 来控制输出节奏，内存始终只存在当前正在处理的一小块数据

### 安全便捷
从LLM提出工具调用到最终执行，需要经过多个安全检查
1. 工具可见性过滤：发送工具列表之前，根据权限规则过滤掉被禁止的工具，模型无法看到不应该使用的工具
2. 输入校验：工具的validateInput会在权限检查之前执行，拒绝格式不合法的参数
3. 权限决策：canUseTool综合考量权限模式、工具危险等级、用户历史决策等因素，做出允许/拒绝/询问的决策
4. 运行时防护：工具执行过程中仍有沙箱限制、超时控制、输出大小限制等防护措施

而白名单方案：同一个Bash工具在同一个命令模式下，在不同参数下的风险等级完全不同，没法精细判断

### 缓存感知
Prompt缓存可以显著降低成本和延迟
- 系统Prompt稳定：确保工具列表不变的情况下，Prompt的字节内容保持一致，从而命中API侧的缓存
- sub-agent缓存共享：Fork模式下的sub-agent会继承renderdSystemPrompt，避免生成银配置变化而不同的Prompt，保证缓存命中率
- 消息历史不可变：已发送给API的消息不回被修改，只有追加新消息的操作，保证了缓存键的稳定性

### 渐进式能力拓展
| 扩展级别 | 机制 | 适用场景
| :--- | :--- | :--- 
| **工具 (Tool)** | 实现 `Tool` 类型接口 | 添加新的原子操作能力 |
| **技能 (Skill)** | Markdown + 脚本的声明式工具 | 封装可复用的任务模板 |
| **插件 (Plugin)** | 带生命周期的工具包 | 组织相关工具和配置 |
| **MCP 服务器** | 标准化协议的外部工具集成 | 第三方工具生态 | 

### 不可变状态流转
核心状态存储由一个store完成，实现不可变状态流转，使状态变化可预测、可追溯、可调试
- Update：状态更新接收一个 `(prev: T) => T` 函数，确保状态的每次更新都基于前一个状态
- 引用相等性检查：只有引用变更时才会触发通知，避免不必要的渲染
- 订阅模式：监听器通过集合管理，返回清理函数，防止内存泄漏
