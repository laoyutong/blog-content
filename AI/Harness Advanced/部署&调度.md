## 概述
**传统 Web 应用是毫秒级响应、无状态的，而Agent 是分钟级执行、有状态、有副作用的长任务。**

传统 Serverless（Lambda 最长 15 分钟、Vercel Functions 免费版 60 秒）的超时限制、无状态设计、冷启动开销，对 Agent 来说几乎不可用

## 长驻进程
最简单的方案，通过**一个 Node.js 或 Python 服务，同时处理 API 请求和 Agent 执行，部署到一个长驻容器上**。用户发请求，服务端开一个 SSE 连接，Agent 在同一个进程里执行任务，token 流式推给用户。核心要求就一个：**没有超时限制**，给 Agent 充分的时间去跑

## 状态持久化
需要考虑网络断了、服务器重启了、内存溢出了等**Agent 跑到一半进程挂了的情况**

核心原则是**在执行高风险操作之前，先把当前状态持久化**

Claude Code 用 **JSONL 格式的 append-only 日志**来记录整个对话过程，每一条消息（用户输入、模型回复、工具调用、工具结果）都作为单独的一行 JSON 追加到文件末尾。**写入是原子的**，**恢复也很简单**


Agent服务的参考思路，**Postgres 负责"不能丢"的数据，Redis 负责"要读快"的数据**
- **Postgres 做主存储**，对话记录、工具调用日志、任务状态、成本统计，全部写进去
- **Redis做缓存层**，主要包括：
	- **活跃会话的上下文**：Agent 每轮对话都要读完整的消息历史来构建上下文，如果每次都从 Postgres 查，频繁的 IO 会拖慢响应
	- **用户级的速率限制和 token 计数**：高频读写操作，每个 API 请求都要检查"这个用户今天还剩多少额度"
	- **分布式锁**：多个 Worker 处理同一个用户的请求时，需要防止并发冲突，比如两个请求同时修改同一个会话的状态

工具调用最好是**幂等的**。同样的输入执行两次，结果应该一样。比如"创建文件 A 内容为 X"是幂等的，但类似"在文件 A 末尾追加一行"的行为不是幂等的。崩溃恢复时可能需要重新执行上一次的工具调用，如果工具不幂等，重新执行就会产生"副作用"。所以，设计工具的时候尽量往幂等的方向靠

## 沙箱
Agent会执行代码，包括跑测试、安装依赖、编译项目等，需要通过**沙箱隔离**给 Agent 一个受限的环境，让它只能做允许的事情

主流方案：**云端 Agent 用 microVM 服务（如 E2B），本地 Agent 用 OS 级权限控制**

### 云端 Agent：E2B 微虚拟机
[E2B](https://e2b.dev/) 底层用的是 Firecracker（AWS Lambda 同款技术），给每个 Agent 会话分配一个轻量虚拟机，有自己独立的操作系统内核，不是 Docker 那种共享内核的”隔板间“，而是一个真正的独立房间。启动只要 125ms，内存开销约 5MB。

装个 SDK，三行代码就能创建一个沙箱、执行命令、拿到结果：

```ts
import Sandbox from "@e2b/code-interpreter"

// 创建一个沙箱（125ms 启动）
const sandbox = await Sandbox.create()

// 在沙箱里执行代码
const result = await sandbox.runCode("print('Hello from sandbox!')")
console.log(result.text) // "Hello from sandbox!"

// 也可以跑 shell 命令
const proc = await sandbox.commands.run("ls -la /home/user")
console.log(proc.stdout)

// 用完关掉
await sandbox.kill()
```
在 Agent 的工具调用里集成也很直观：
```ts
const tools = {
  execute_code: async ({ code, language }) => {
    const sandbox = await Sandbox.create()
    try {
      const result = await sandbox.runCode(code, { language })
      return {
        stdout: result.text,
        stderr: result.error,
        exitCode: result.exitCode,
      }
    } finally {
      await sandbox.kill()
    }
  },

  run_tests: async ({ testCommand }) => {
    const sandbox = await Sandbox.create()
    // 先把项目文件写进沙箱
    await sandbox.files.write("/home/user/app/index.ts", projectCode)
    await sandbox.files.write("/home/user/app/test.ts", testCode)
    // 装依赖、跑测试
    await sandbox.commands.run("cd /home/user/app && npm install")
    const result = await sandbox.commands.run(
      `cd /home/user/app && ${testCommand}`
    )
    await sandbox.kill()
    return { output: result.stdout, errors: result.stderr }
  },
}

```

### 本地 Agent：OS 级权限控制
跑在用户电脑上的本地工具（Claude Code、Cursor 等），直接用操作系统自带的安全机制限制 Agent 能做什么

Claude Code 的文件系统默认只读（只有工作目录可写），除非加白名单或者加上 `--dangerously-skip-permissions` 命令行参数。操作系统强制执行这些规则，Agent 想违反也做不到。好处是**几乎零开销**，Agent 直接在本机跑，只是权限被限制了
