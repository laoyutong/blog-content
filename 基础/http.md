## 缓存

### 强缓存

#### Expires

绝对时间，依赖客户端时间，时间不准会导致缓存失效

#### Cache-Control

- max-age：缓存最大有效时间
- public：任何途径都可缓存，包括代理
- private：不能被代理服务器缓存
- no-cache：强制协商缓存
- no-store：不走缓存
- no-transform：不转换


### 协商缓存

协商缓存需要发送请求到服务器，由服务器判断资源是否更新

#### Last-Modified / If-Modified-Since

- 只能精准到秒，无法区分在1s内修改了多次
- 没法识别修改时间变了但是内容没变的情况

#### ETag / If-None-Match

- 精确到内容变化，时间无关

### 最佳实践 

- 静态资源(图片/JS文件等)：强缓存 + 文件名hash
- HTML文件：协商缓存 + ETag

## 状态码

- 101：协议切;常用于WebSocket
- 200：请求成功
- 201：请求成功切服务器创建了新资源;常用于POST
- 204：请求成功，但响应报文不包含实体主体；常用语DELETE
- 301：永久重定向；会消费响应头的Location
- 302：临时重定向
- 304：协商缓存成功
- 400：语义或参数错误
- 401：未授权
- 403：禁止访问，通常是权限不足
- 404：资源不存在
- 405：请求方法不允许
- 500：通用服务器错误
- 502：网关错误
- 503：服务不可用；通常因为超负荷或停机维护
- 504：网关超时

## 连接的建立&断开

### 三次握手

1. 客户端发送序列号x
2. 服务端生成序列号y，并将x+1作为确认号发回
3. 客户端收到消息，并将y+1作为确认号发回

### 四次挥手

1. 客户端发送结束报文
2. 服务端回复收到，但数据可能没发完
3. 服务端发送结束报文
4. 客户端回复收到

## HTTPS

### 概要

- 通过非对称加密（公钥进行加密后，只有这个对应的私钥才能解密）的方式，传输对称加密（用一个密钥实现加密和解密）的密钥
- 公钥是服务器发放的，通过数字证书来验证服务器身份，确保网站真实可信

### 详细流程

1. 客户端发送支持的TLS版本和密码套件列表以及一个客户端随机数；服务端选择一个加密算法，并生成一个服务端随机数
2. 服务端发送CA数字证书，证书内包含服务器的公钥；客户端检查证书的合法性
3. 客户端生成第三个随机数，并用证书里的公钥进行加密，发送给服务端；服务端收到后，使用只有自己知道的私钥进行解密
4. 双方利用这三个随机数生成密钥，用于后续通信的对称加密


## HTTP2
- 二进制分帧：将请求和响应拆分成更小的二进制帧，不再直接传输纯文本
- 多路复用：允许在一个TCP链接上并行发送多个请求和响应，避免队头阻塞问题
- 头部压缩：可以将冗长的HTTP头字段进行压缩，减少重复数据的传输，降低网络开销
- 服务器推送：允许服务器在客户端主动请求之前推送资源；如在浏览器还没解析HTML之前，主动把需要的CSS和JS推送过去
